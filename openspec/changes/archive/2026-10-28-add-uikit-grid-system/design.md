# Design

## Context

- Skeleton exists at `packages/uikit/src/components/Grid/`: `Grid.tsx` (polymorphic via `types/polymorphic.types.ts`, `Grid.Cell = GridCell` static), `GridCell/GridCell.tsx`, barrels, and an empty `Grid.module.scss`. `GridCell` imports `../Grid.module.scss` and applies `styles.grid` (a copy-paste bug). Both call signatures default `C` to `typeof Fragment` while the runtime default is `'div'`.
- `src/assets/scss/variables.scss` holds one map, `$duckdice: (spacing: 4px, breakpoints: (...11 tokens...))`. The tokens are listed alphabetically, **not** by width (`md_max` 960px sorts after `md` 1025px). `src/assets/scss/mixins.scss` is empty. No SCSS in the package currently `@use`s either file.
- The same breakpoint values are duplicated in TS (`constants/breakpoints.const.ts`, `BreakpointToken`), which `useBreakpoint` uses with `min-width` semantics.
- The library build runs `themeCssSplit`, which requires `[data-theme]` to lead every themed selector and splits rules inside `@media` per theme (see `openspec/specs/uikit-theme-stylesheets`). Storybook keeps unsplit CSS and switches `data-theme` between `duckdice` and `tower`.
- Only Biome (pre-commit) and per-package `tsc -b` gate changes. Nothing in this design relies on ESLint, Prettier, or a turbo `lint`/`test` script; SCSS is not formatted by any enforced tool.

## Goals / Non-Goals

**Goals:**
- Pure-CSS responsive behavior (no `useBreakpoint`/JS media queries), so layout is correct on first paint and under SSR.
- One SCSS source for the grid, generated per theme from that theme's variables map.
- Arbitrary non-negative spacing multipliers (including fractions) without a class per value.

**Non-Goals:**
- Unifying the TS and SCSS breakpoint sources.
- Supporting the `tower` theme now (no variables map; see proposal).
- Cell offsets, ordering, `'auto'` spans, alignment props, responsive spacing.

## Decisions

### 1. Gutters via `gap` with gap-aware widths (not Bootstrap padding + negative margins)
`.grid` is `display: flex; flex-wrap: wrap; column-gap: <col>; row-gap: <row>`. A cell spanning N columns gets
`flex: 0 0 W; max-width: W; min-width: 0` with
`W = calc((100% - 11 * var(--grid-col-gap)) / 12 * N + (N - 1) * var(--grid-col-gap))`.
This satisfies the "spans sum to 12 fill the row" and alignment requirements exactly.
- *Alternative — Bootstrap gutters* (cell padding, negative margins on the row): gives the row-gap no clean equivalent, forces padding onto cells (consumers can't style cell boxes freely), and needs `overflow` handling for negative margins. Rejected.
- `display: none` cells are not flex items, so hidden cells take no gap — matches the "hidden" requirement for free.

### 2. Spacing passed as CSS custom properties, scaled in SCSS
`Grid` writes the multipliers to inline style: `--grid-col-spacing: colSpacing ?? spacing ?? 0` and `--grid-row-spacing: rowSpacing ?? spacing ?? 0`, merged with (and overridable by) the consumer's `style`. Per theme, SCSS turns them into lengths on `.grid`:
`--grid-col-gap: calc(var(--grid-col-spacing) * #{map.get($vars, spacing)})` (same for row), then `column-gap: var(--grid-col-gap)`. Cells read `--grid-col-gap` inherited from their parent grid.
- Both variables are **always** set (defaulting to `0`), so a nested `Grid` never inherits its parent's spacing.
- *Alternative — generated `.spacing-0…N` classes*: caps the range, rules out fractions, and multiplies CSS (×3 props). Rejected.
- Negative values are excluded at the type level only (`number`); not clamped at runtime.

### 3. Span classes generated by SCSS loops, chosen by `classnames` in `GridCell`
Generated classes per theme: `.span-1…12`, `.span-hidden` (unconditional), then for each breakpoint token in ascending width, inside `@media (min-width: <value>)`: `.<token>-1…12`, `.<token>-hidden`. `GridCell` builds `cn(styles.cell, span && styles[`span-${span}`], …tokens.map(t => props[t] && styles[`${t}-${props[t]}`]), className)`.
- Cascade (widest wins, carries upward) comes from source order: all span classes have equal specificity, and media blocks are emitted narrow → wide. Prop order and name never matter.
- Base `.cell` defaults to the 12-column width, covering "no span" behavior.
- Numeric span classes also set `display: block` so a wider numeric span re-shows a cell hidden at a narrower breakpoint; `-hidden` classes set `display: none`.
- *Alternative — inline `--span` custom property per breakpoint*: inline styles can't contain media queries, so it would need JS breakpoint detection. Rejected (Goal: pure CSS).

### 4. Sorting breakpoints in Sass
Because the map is alphabetical, add a `sort-by-value($map)` function (simple selection sort returning an ordered list of keys) and a `breakpoint-up($name, $breakpoints)` mixin emitting `@media (min-width: …)`, both in `assets/scss/mixins.scss` (via `@use 'sass:map'`/`'sass:list'`). Reordering `variables.scss` by value was considered but would silently break the cascade whenever someone adds a token alphabetically.

### 5. Theme generation
`variables.scss` gains `$themes: (duckdice: $duckdice);`. `Grid.module.scss`:
```scss
@use '../../assets/scss/variables' as vars;
@use '../../assets/scss/mixins' as mx;
@each $theme, $config in vars.$themes {
  [data-theme='#{$theme}'] { .grid { … } .cell { … } .span-N { … } … }
}
```
`[data-theme]` leads every selector (required by `themeCssSplit`); Sass bubbles `@media` above the nested rules, which the plugin splits correctly. No `@keyframes`, so no cross-theme name collision. Adding `tower` later = add `$tower` + register it in `$themes`.

### 6. Types and file layout
- `Grid.types.ts`: `GridSpacing = number`.
- `GridCell/GridCell.types.ts`: `GridCellSpan = 1 | 2 | … | 12 | 'hidden'`; `GridCellBreakpointProps = Partial<Record<BreakpointToken, GridCellSpan>>` reusing the existing `BreakpointToken` type; `GridCell.const.ts` holds the token list in ascending width order (`GRID_CELL_BREAKPOINTS`) for building class names.
- `GridCellProps` = `PolymorphicProps<C, { className?; span?: GridCellSpan } & GridCellBreakpointProps>`; `GridProps` adds `spacing?`, `colSpacing?`, `rowSpacing?`, `style?`.
- Fix the call-signature default to `C extends PolymorphicElement = 'div'` in both components.
- Barrels keep the existing separate `export type {}` / `export {}` style and add the new types; root `src/index.ts` already exports `Grid` and follows its own combined-syntax style — extend it in that style (adding `GridCell`/types) rather than reformatting it.
- Props stay destructured in the signature; Biome's sorted keys/attributes/interface members apply.

## Risks / Trade-offs

- [`display: block` on numeric span classes overrides a consumer `display` on the cell element] → Document in the story that a cell is a block box; put flex/grid layouts on a child. Consumer `className` can still win with higher specificity.
- [Breakpoint values duplicated in SCSS and TS can drift] → `GridCell.const.ts` reuses `BreakpointToken` so a token added only in SCSS fails at type-check when its class is missing from the list; values themselves remain unsynchronized (noted in proposal).
- [CSS size: 12 breakpoints × 13 classes ≈ 156 rules per theme] → Acceptable; small flat rules, emitted only into the matching theme file.
- [Grid unstyled under `tower` in Storybook] → Expected until a `$tower` map exists; the story notes it.
- [Spec scenarios are verified manually in Storybook only] → No test runner exists; adding one is out of scope.

## Migration Plan

Additive; `Grid` has no consumers yet. Rollback is reverting the change.
